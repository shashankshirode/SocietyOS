# Society OS Resident Page Experience Matrix

Date: 2026-08-21

## Scope and architecture

The resident application contains 254 route declarations across 11 resident-facing navigators. The declarations include five shell tabs, nested-stack entry points, compatibility aliases, and repeated routes exposed from Home. The route contract is intentionally preserved; this matrix groups routes by the physical-world ecosystem they represent.

The functional spine is:

- React Navigation 7 native stacks and bottom tabs.
- Capability guards under `src/features/residentCapabilities`.
- Active-home context from `residentHomeContextStore`, persisted selection, and session role remapping.
- Residence-scoped repository contexts containing society, unit, resident profile, locale, timezone, and `dataScopeKey`.
- API/mock repository selection through `createRepository`.
- React Native Reanimated 4 plus the existing reduced-motion hook.
- Shared loading, error, modal, bottom-sheet, typography, status, and motion primitives.

## Shared primitives

- `ResidenceContext`: society, unit, relationship and status with a single authoritative switch trigger.
- `ContextField`: bounded spatial canvas for domain objects.
- `ResidencePulse`: home-centered temporal field, not a score.
- `SpatialNode` and `EventMarker`: accessible event objects with semantic state and time.
- `ContextCommand`: one emerging next action bound to permission and authoritative state.
- `LivingTimeline`: chronological structure supporting past/current/upcoming depth.
- `StateSurface`: calm, active, attention, urgent, loading, empty, offline and error presentation.
- `EditorialSection`: typography-led grouping without default card chrome.
- `ProgressiveDetail`: disclosure layer for forms and complex objects.
- `StatusTransition`: reusable real-state transition with reduced-motion fallback.
- `MorphingContainer`: visual continuity wrapper that does not replace navigation or data fetching.

## Motion primitives

- Ambient breath: 4–7 seconds, opacity/scale only, disabled for reduced motion.
- Node arrival/departure: 180–240 ms, small translation plus opacity.
- Context command reveal: 180–220 ms, upward translation plus opacity.
- Sheet/context switch: existing spring physics, selected residence moves forward while prior context recedes.
- State change: 160–260 ms; semantic color plus label/icon change, never color alone.
- Critical transition: immediate focus change, no ornamental delay.

## Architecture risks

1. Route aliases and nested stacks can create duplicate visual entry points; preserve route names and centralize experience components.
2. Dashboard aggregation mixes cross-domain data with partial section states; never interpret an error/offline section as empty.
3. Active-home switching updates repository scope, persisted context and session role; local-only switching would leak stale home data.
4. Many screens contain generated style helpers narrowed to historical literal colors; semantic-token migration must keep helper types broad.
5. Visible copy is enforced by a localization verifier; new experience language must enter message catalogs.
6. Reanimated and React Native Animated coexist; new primitives should standardize on Reanimated while retaining existing sheet behavior.
7. Feature flags and capability guards exist at stack and screen levels; contextual commands must use the same permissions.
8. Financial, visitor, booking, document and emergency states are authoritative; motion may visualize transitions but cannot manufacture them.
9. The resident graph is large enough that destructive global replacement is unsafe; migrate ecosystem by ecosystem with tests after each phase.
10. Existing tests directly reference legacy components, so deprecated components require reachability analysis before deletion.

## Recommended implementation sequence

1. Tokens, reduced-motion-aware motion primitives and foundational spatial primitives.
2. Resident shell and residence context continuity.
3. Residence Pulse / Home.
4. Activity, Services and residence switching.
5. Visitors, parcels, finance, complaints and facilities as separate high-value ecosystems.
6. Household/lifecycle, documents/NOC, domestic help and parking.
7. Community/connect/messages, governance, emergency, then notifications/profile.
8. Cross-ecosystem continuity, accessibility, localization and visual consistency audit.

Only `ResidentHome` is authorized for structural redesign in the current phase.
